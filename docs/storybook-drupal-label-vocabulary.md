# Storybook / Drupal label vocabulary audit

The control parity audit (`docs/storybook-drupal-control-parity.md`, from
yalesites-org/component-library-twig#728) compared controls by their internal option keys, such as
`one`..`six` or `full` / `reduced` / `mini`. Editors never see those keys. This audit compares the
labels people actually read: the control label and every option label, in Storybook and in the
Drupal editor form. It flags each label that does not follow the vocabulary in
`ys_themes.component_overrides.yml`, including case and order, and recommends a fix. It was
produced for yalesites-org/YaleSites-Internal#1796. In the tables below, "the parity audit" means
that yalesites-org/component-library-twig#728 document.

**No Drupal labels were changed.** Every "Change Drupal" item below is a recommendation for a
separate ticket. Editor-visible label changes are out of scope here.

## How to read this audit

One row per row of the parity audit: its 281 Storybook controls and its 10 Drupal-only controls,
in the same order and under the same component names.

- **Storybook label** is what the Controls panel shows: the control `name`, then each option as
  displayed. Storybook 8 shows an array option as its raw value unless the story sets
  `control.labels`, and shows the keys of an object option as its labels. Only
  `Organisms/Global Elements/In This Section` `collectionNavDisplay` sets `control.labels` today.
- **Drupal label** is what an editor sees: the field or form element title, then each option
  label in form order, followed by the file it came from. `none` means Drupal has no editor
  control for it. A related field is named where one exists.
- **Match?** is `Match`, `Mismatch`, `No Drupal control`, `No Storybook control` (the Drupal-only
  rows) or `Label not found`.
- **Issue** names the kind of difference: keys shown instead of labels, case, order, synonym,
  missing option, or control label wording.
- **Recommendation** is `Change Storybook`, `Change Drupal (separate ticket)` or `Leave`, with
  the reason, or `None needed.` for a `Match` row.

Rules used to reach a recommendation:

1. **Option labels.** Storybook should show the labels editors see. Where Storybook shows a key,
   the fix is to add `control.labels` in the story or props helper and keep the key as the value.
   Keys are not renamed, because the Twig templates consume them.
2. **Control labels.** Change Storybook when the words differ (for example `With Animation` vs
   `Enable Animation`). Leave it when the only difference is case, a component-name prefix, or the
   documented `(dial)` / `(lever)` suffix and "[Component] Theme" pattern
   (`components/_storybook/README.md:402`, `components/00-introduction/theme-system.mdx:237`).
3. **Drupal labels.** Recommend a Drupal change only when a Drupal label breaks the standard
   vocabulary below, or two Drupal forms word the same option differently.
4. **Content slots.** Content and structural rows are recorded for completeness. Their Storybook
   names describe Twig props and their Drupal labels name fields on a form, so a difference there
   is recorded and left alone.

Controls with no standard in this list, such as padding, focus, or the sitewide theme levers,
were compared against the Drupal label that backs them. The overrides file itself follows the
standard everywhere it applies.

Synonyms the ticket asked about:

- `Outdent` for `Offset`: found in Drupal, `ProfileMetaBlock.php:202` (Profile Meta image style).
  Storybook also uses the key `outdent` there.
- `Small` for `Short`: not found in any `*-props.yml`, story override, or Drupal component form.
  The only `Small` in `config/sync` is `webform.webform_options.size.yml`, which is not a
  component control.
- `Color 1` for `One`: not found on either side. Storybook shows the key `one` instead, which is a
  case difference from `One`.

Other synonyms found: the Storybook keys `reduced`/`full` for `Short`/`Tall`, `floated` for
`Inline`, `site`/`max` for `Contained`, and `highlight`/`site` for `Medium`/`Large` (all shown as
labels today); `Online` for the Drupal term `Virtual`; `Eyebrow` for `Teaser lead-in`; and
`primary`/`secondary` for `Filled`/`Outline` in the Action Banner button style.

### Candidates for a follow-up Drupal ticket

These are recommendations only. None were made in this change.

1. **Section theme option case.** `Default - no color` should be `Default - No Color`, as in every
   block dial in the overrides file. `YSLayoutOptions.php:104`. Affects the six atom
   `sectionTheme` rows and Templates/Layout `theme`.
2. **Section theme control title.** The section form titles the picker `Component theme`
   (`YSLayoutOptions.php:101`). Storybook and the parity audit call it `Section Theme`, and it sits
   on the section, not a component. Suggest `Section theme`.
3. **Profile Meta image style.** `Outdent` should be `Offset`, the standard used by Content
   Spotlight and Wrapped Image. `ProfileMetaBlock.php:202`.
4. **Taxonomy Display theme.** The `Theme` select (`TaxonomyDisplayBlock.php:153-168`) has no
   `Default - No Color` option, though the block's default configuration seeds `default`. Adding
   it changes the option set, so it depends on the parity audit decision for that row.
5. **Padding labels.** The block field `field_padding_options` and the section `padding_options`
   form word the same four options differently (`Padding on both top and bottom` vs `Default`,
   `No padding (removes both top and bottom padding)` vs `No padding (top and bottom)`). Pick one
   set for both. `field.storage.block_content.field_padding_options.yml`,
   `ys_layouts.module:561-569`.
6. **Wrapped Image position field label.** Low priority. `Position` could be `Image Position`, as
   on Content Spotlight. `field.field.block_content.wrapped_image.field_style_position.yml`.
7. **Social link typo.** `X (formally Twitter)` should be `X (formerly Twitter)`. It also feeds
   the footer form field title `X (formally Twitter) URL`. `SocialLinksManager.php:20`.
