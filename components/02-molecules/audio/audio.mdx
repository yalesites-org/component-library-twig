# Audio Player

The audio component wraps an HTML5 `<audio>` element in a custom, keyboard-accessible player with play/pause, a draggable progress bar with elapsed and total time, playback-speed selection, and a volume control. An optional label can be shown above the player, and an optional transcript below it. In Drupal the audio source is supplied by the block's media field rather than a URL prop.

## With Transcript

A transcript renders below the player as ordinary page text, styled like the Video description, under a visible "Transcript" button that shows and hides it. Once JavaScript runs the transcript starts collapsed, so a long one does not push the rest of the page down; without JavaScript it stays open. Either way it is reachable without playing the audio, which is what WCAG 2.1 Level A (SC 1.2.1) asks of prerecorded audio.

## Player Controls

- **Play / Pause**: Toggles playback; the button swaps between the play and pause icons.
- **Progress bar**: A range slider showing playback position; drag to seek. The current and total time are displayed alongside it (`m:ss`).
- **Playback speed**: A gauge toggle opens a menu of 0.5x, 1x, and 2x options. The whole speed control area (including the visible active label) is the click target, not just the icon.
- **Volume**: A mute toggle plus a range slider. The volume control is hidden below the mobile breakpoint, where the device's physical volume controls take over.

## Technical Specifications

- **Atomic Level**: Molecule
- **Template**: `yds-audio.twig`
- **Styles**: `yds-audio.scss`
- **Behavior**: `yds-audio-player.js` (attached via the `audio-player` asset library in the Atomic theme)

### Accessibility

- **Keyboard**: All controls (play/pause, progress, speed toggle and options, volume) are native `<button>` / `<input>` elements and are keyboard focusable and operable.
- **Accessible names**: Each control has a visually-hidden label or `aria-label` (for example "Play the Audio File", "Audio Playback Progress Bar", "Volume").
- **State**: The speed toggle and the transcript toggle expose `aria-expanded`; the volume mute toggle exposes `aria-pressed`.
- **Transcript**: An optional transcript renders as page text after the player, under a native `<button>` labelled "Transcript" with `aria-expanded` and `aria-controls`. The `audioTranscript` behavior collapses it on load; the markup itself renders it open, so it is reachable without playing the audio or running JavaScript.
- **Fallback**: Browsers without HTML5 audio support see the message "Your browser does not support the audio element."

### Responsive Behavior

- The player scales to the content width of its container.
- Below the mobile breakpoint the volume control is hidden (device volume handles it) while the progress bar and playback controls remain usable.

## Implementation Notes

### Basic Audio Embed

```twig
{{ include('@molecules/audio/yds-audio.twig', {
  audio_embed__content: 'Get Your Kicks on Route 66',
  audio_embed__url: 'https://example.com/audio.mp3',
}) }}
```

### With a Transcript

```twig
{{ include('@molecules/audio/yds-audio.twig', {
  audio_embed__content: 'Listen to this content',
  audio_embed__url: 'https://example.com/audio.mp3',
  audio_embed__transcript: '<p>Full transcript of the audio.</p>',
}) }}
```

The transcript is passed through the text atom unescaped, to support Drupal's rich-text field output. In Drupal it comes from the Audio block's Transcription field, and a player with a transcript gets the `audio-embed--has-transcript` modifier, which Editoria11y uses to skip its "Does this audio have a transcript?" check.

In Drupal the audio source is provided by the block's media field, so `audio_embed__url` is used mainly for the Storybook preview and standalone examples.
